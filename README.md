# 하천·도로·철새도래지 현황 PPTX

위치(주소 또는 위경도)를 입력하면 **인근 하천·도로**와 **철새도래지 현황**을 조회해, 16:9 PPTX **2장**으로 만드는 브라우저 웹앱입니다.

| 슬라이드 | 내용 |
| --- | --- |
| 1 | 하천·도로. 슬라이드 전체가 지도(기본: 브이월드 위성지도). 하천·호수는 거리(노랑)+이름(하늘색) 말풍선, 국도는 파란 타원·지방도는 노란 사각 번호 표지와 `국도 16번` 같은 이름표 |
| 2 | 철새도래지. 일반지도(기본: 브이월드 일반지도) 위에 국립생물자원관 조사구역 경계, 도래지 이름·개체수(회색 칸)와 구역 경계까지의 거리(하늘색 칸) |

지도 그림은 이미지로(2장은 배경과 조사구역 경계가 각각 별도 이미지), 말풍선·이름표·거리표는 PowerPoint에서 고칠 수 있는 도형으로 들어갑니다. 말풍선에 못 올린 나머지 하천·도로·도래지 목록은 각 슬라이드의 발표자 노트에 있습니다.
표시 기준은 원본 웹앱을 따릅니다. 결과 화면의 세 표(하천·호수 / 국도·지방도 / 철새도래지)는 같은 형식(체크 · 번호 · 이름 · 구분 · 거리 · 비고)이고, **체크한 항목만 지도에 올라갑니다**(바꾸면 미리보기와 PPTX에 바로 반영). 처음 체크 상태: 하천·호수는 원본 기준(국가·지방하천, 이름 있는 호수·저수지만 대상; 거리 구간 1·1.5·3·5km마다 최대 2곳, 국가하천 → 지방하천 → 호수·저수지 순, 면적 큰 순; 10만㎡ 이상 호수·저수지는 항상), 국도·지방도는 가까운 6개 노선, 철새도래지는 지도 범위에 걸치는 조사구역 **전부**(반경 밖이라도 지도에 보이면 포함)입니다. 체크를 해제한 하천·호수·도로는 말풍선·번호 표지와 앱이 덧그린 하천 면·호수 면·흰 도로선도 함께 사라집니다(배경지도에 원래 찍혀 있는 하천·도로는 그대로). 표에 없는 반경 밖 도형은 그리지 않습니다. 지도는 반경 원이 화면 높이의 약 96%를 채웁니다. 철새도래지 칸은 경계점 바로 아래에 두고, 겹치면 위치를 옮기지 않고 글자와 칸을 줄여 해결합니다(기준점 이름 칸이나 경계점 바로 곁 자리로 어쩔 수 없을 때만 예외).

**GIS 엑셀(선택)**: 입력 화면에서 `.xlsx`를 올리면(첫 행 열 이름 `구분·위도·경도`, 선택 `제목·날짜·내용`) 철새도래지 슬라이드 지도에 주황 점을 찍고, 기준점까지의 거리(주황 칸)와 제목·구분을 도래지와 같은 방식의 칸으로 올립니다. 같은 제목이 1km 안에 여러 건이면 한 칸으로 묶어 구분과 건수를 적습니다. 결과 표에 GIS 지점 표(체크칸 포함)가 생기고, 철새도래지 표의 "권역 내 GIS 구분"에는 그 조사구역 안에 든 엑셀 지점의 구분과 건수가 나옵니다. 점과 칸의 색은 엑셀 `표현색` 열의 색을 따릅니다(칸에 적힌 `#RRGGBB`·색 이름 값, 없으면 그 칸의 배경색; 둘 다 없으면 주황). 같은 제목이 묶인 칸은 가장 최근 건의 색입니다. 2장의 글씨는 기본 18pt이고, 겹치면 그보다 줄어듭니다. 파일은 브라우저에서만 읽습니다(`src/gis.js`, 외부 라이브러리 없음). 철새도래지 체크를 해제하면 보라색 구역도 지도에서 사라집니다.
도로의 통행량(예: "2,563대 통행")은 내장 데이터에 없어 넣지 않습니다. 필요하면 PowerPoint에서 이름표 글상자에 직접 적으세요.

## 사용법

1. 위도·경도를 입력하거나, "주소·장소명으로 찾기"에서 후보를 골라 위치를 정합니다. 브이월드 인증키 칸도 이 항목 안에 있습니다.
2. 하천·도로 반경(1.5/3/5 km), 철새도래지 반경(20/30/50 km), 조사월, 슬라이드별 배경지도를 고릅니다(기본: 하천·도로 위성, 철새도래지 일반).
3. **조회하고 미리보기** → 결과 확인 → **PPTX 저장**.

지도 배경(슬라이드마다 따로 선택): 브이월드 일반/위성/하이브리드(브이월드 인증키 필요) · OpenStreetMap(키 불필요) · Sentinel-2(Google Earth Engine 로그인 필요) · 배경 없음. 기본값인 브이월드 지도는 인증키를 넣어야 조회됩니다. 키가 없으면 OpenStreetMap 등으로 바꾸세요.
주소 검색은 브이월드 인증키가 있으면 브이월드(지번·도로명·장소명), 없으면 OpenStreetMap Nominatim을 씁니다.

## 배포 (Cloudflare Pages)

빌드가 필요 없습니다. 저장소 루트를 그대로 배포합니다.

- Git 연동: 빌드 명령 없음, 출력 디렉터리 `/`.
- 또는 Direct Upload로 이 폴더의 내용을 올립니다.
- `_worker.js`는 `/api/*`만 처리합니다(`_routes.json`). 나머지는 정적 파일입니다.
- Cloudflare가 Workers 방식(Workers Builds)으로 연결하는 경우에는 `wrangler.jsonc`가 설정을 담당합니다: `_worker.js`를 진입점으로, 저장소 루트를 정적 파일(`.assetsignore`로 소스·테스트 제외)로 올리고 `/api/*`만 워커가 먼저 처리합니다. 배포 명령은 `npx wrangler deploy`입니다.

브이월드 키를 쓰려면 배포된 주소를 키의 허용 URL에 등록하세요. Earth Engine은 Cloud 프로젝트 ID와 OAuth 웹 클라이언트 ID(승인된 JavaScript 원본에 배포 주소)가 필요하며, 클라이언트 보안 비밀번호나 서비스 계정 키는 입력하지 않습니다.

## 로컬 실행·테스트

```sh
node tools/dev-server.mjs            # http://127.0.0.1:8788/  (정적 파일 + /api/* 는 _worker.js 호출)
node tools/dev-server.mjs --mock     # 국립생물자원관 대신 가짜 응답(오프라인 확인용)
npm test                             # 단위·정확도 테스트 (Node 22, 의존 패키지 없음)
node test/e2e.mjs /tmp/e2e           # Chrome headless로 조회→PPTX 저장까지 점검 (google-chrome 필요)
```

`npm test`의 `test/analysis.test.mjs`는 타일 분할 결과가 **원본 전체를 전수 탐색한 값**(`test/fixtures/expected.json`)과 같은지 확인합니다(하천·호수·도로, 12개 지점).

## 데이터와 타일

내장 데이터는 `assets/tiles/`의 격자 타일입니다. 조회 한 번에 기준점 주변의 타일 몇 개(수백 KB)만 읽습니다.
(이전 버전은 도로 68만 피처 약 155MB를 한 번에 파싱해 메모리가 부족해질 수 있었습니다.)

| 레이어 | 격자 | 원본 |
| --- | --- | --- |
| `rivers` | 0.25° | 기후에너지환경부 하천 공간정보 (2026-09-14), 면 도형. 타일 경계에서 잘라 저장하며, 잘린 면 때문에 생긴 변은 거리 계산에서 제외 |
| `lakes` | 0.25° | 국토지리정보원 연속수치지형도 호수·저수지(이름 있는 도형). 도형 전체를 겹치는 타일마다 복제 |
| `roads` | 0.1° | 국도·지방도 중심선 |

타일을 다시 만들려면 원본 `rivers.json.gz`, `lakes.json.gz`, `roads-001..008.json.gz`를 `data-src/`에 두고:

```sh
python3 tools/build_tiles.py --src data-src --out assets/tiles
python3 tools/make_fixture.py --src data-src --out test/fixtures/expected.json   # 검증 기대값 갱신
```

`data/nibr-boundaries.json`은 철새 조사구역 경계의 저장본입니다. `/api/boundaries`가 실시간 조회에 실패하면 이 파일로 대신합니다.

## 거리 계산 기준

- 기준점에서 GIS 도형까지의 최단 직선거리(m). 면 도형 **안에 있으면 0**(표에는 "구역 안")이고, 밖이면 경계까지의 거리입니다.
- 하천은 하천 코드, 호수는 도형 단위로 하나로 합칩니다. 호수·저수지는 **이름이 있는 도형만** 들어 있어 이름 없는 소규모 저수지는 빠집니다.
- 국도·지방도는 노선별 최단거리이며 이름은 `국도 16번`, `지방도 820번` 형식입니다. 한 도로 도형에 여러 노선번호(예: `제44호,제56호`)가 있으면 각각에 반영합니다. 끝이 잘려 번호를 알 수 없는 항목은 버립니다.

## 알려진 한계

- **국립생물자원관 연동은 공개 API가 아니라 사이트 내부 AJAX**(`/bird/home/geo/searchAjax.do`)를 이용합니다. 사이트가 바뀌면 조사월·개체수 조회가 깨질 수 있습니다. 개체수만 실패하면 거리·경계는 보여 주고 "자료 없음"으로 표시하며 슬라이드에도 그렇게 적습니다. 이용약관·공공누리 조건은 배포 전에 확인하세요.
- **Sentinel-2(Earth Engine)는 이 저장소에서 실제 로그인으로 검증하지 못했습니다.** 기본값은 CDN의 `@master` 스크립트(버전 미고정)입니다. `tools/vendor-ee.sh`로 `vendor/ee_api_js.js`를 저장해 커밋하면 그 파일을 우선 사용합니다.
- 브이월드 지도·주소 검색과 OpenStreetMap 타일·Nominatim은 외부 서비스입니다. OSM 타일은 슬라이드 한 장당 수십 장을 받으므로 대량·반복 사용은 이용 정책에 맞지 않습니다.
- 데이터 범위는 대한민국(위도 32~40, 경도 124~132)입니다.

## 이전 버전에서 바뀐 점

- 두 앱(하천·도로 / 철새 리포트)을 하나로 합치고, 두 개의 PPTX를 ZIP으로 묶던 방식을 1개 PPTX(2장)로 바꿨습니다.
- 제거: Leaflet 기반 철새 화면, 숨은 iframe 연동, 읽기만 하고 쓰지 않던 `sessionStorage` 핸드오프, 워커의 사용하지 않던 `/api/geocode`·`/api/maps/vworld`, 워커에 내장돼 있던 경계 데이터 사본, 이전 AI 호스팅 도메인 상수, Overpass 기반 "일반지도"와 브이월드 도로 API, Plus Code 입력, KML·CSV 내보내기. 필요하면 `baseline` 커밋(원본 소스)에서 되살릴 수 있습니다.

## 화면 디자인

웹앱 화면은 [KRDS(범정부 UI/UX 디자인시스템)](https://www.krds.go.kr)의 시각 기준을 따릅니다: 정부 청색(#256EF4) 중심의 색, 회색 스케일, 본문 17px, 버튼 48px·라운드 6px, 입력 48px·라운드 8px, 카드 라운드 12px, 포커스 링, 서체 Pretendard GOV(불러오지 못하면 Pretendard → 맑은 고딕). 스타일은 `src/style.css`의 CSS 변수에 모여 있습니다. 이는 화면만의 변경이며 PPTX 안의 색·글꼴은 원본 웹앱 양식 그대로입니다. KRDS 공식 Figma 파일은 로봇 차단으로 직접 열 수 없어, KRDS 누리집과 공개된 토큰 정리를 참고했습니다.
